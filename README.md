# IONOGUARD

**Reliable Multi User Direct to Cell Satellite Assignment under Ionospheric Scintillation with Conformal Risk Control**

G. Arul Dalton, Department of Computer Science and Engineering, Saveetha Engineering College, Chennai, India
(aruldalton@saveetha.ac.in, ORCID [0000-0002-5981-7176](https://orcid.org/0000-0002-5981-7176))

This repository contains the complete implementation, configuration, trained models and result files for the manuscript submitted to the *IEEE Transactions on Aerospace and Electronic Systems*. Every number, table and figure in the paper is produced by the code here.

---

## 1. What IONOGUARD does

Direct-to-cell (D2C) satellite service connects unmodified smartphones to low Earth orbit (LEO) satellites in mobile bands. In the equatorial region, post-sunset plasma bubbles cause deep ionospheric scintillation on these links, and the few satellites whose links stay clear are wanted by every nearby user. IONOGUARD assigns users to satellites and selects the modulation and coding scheme (MCS) of each link with a reliability guarantee:

| Stage | What it does | Paper | Code |
|---|---|---|---|
| A | Drift-compensated Nadaraya–Watson S4 map from delayed GNSS monitor reports, with self-supervised zonal-drift estimation | Sec. V-A, Eq. (7) | `src/run.py` (`Night`, `future_query`) |
| B | Gradient-boosted correction of the map at the projected pierce points | Sec. V-B | `src/train.py` (`build_models`) |
| C | Regime-conditional conformal risk control on the scheduling decision (Algorithm 2) | Sec. V-C, Eqs. (8)–(9), Prop. 1 | `src/train.py` (`build_models`, `apply_lambda`) |
| — | Online risk control from HARQ ACK/NACK (IONOGUARD-OL) | Sec. V-D, Eqs. (10)–(11), **Theorem 1** | `src/run.py` (`OL_*`), `src/mu.py` (`OL_POL`) |
| D | Receding-horizon link scoring over the ephemeris (Algorithm 1) | Sec. V-E, Eq. (12) | `src/run.py` (`run_night`) |
| E | Exact capacity-constrained joint assignment (b-matching, Hungarian method, Algorithm 3) and its proportional-fair form | Sec. V-F/G, Eqs. (13)–(15), Prop. 2 | `src/mu.py` (`joint_assign`, `run_multi`) |
| — | Lagrangian goodput bound and minimum deferral for any reliable controller | Sec. VI, Eqs. (16)–(17), Props. 3–4 | `src/mu.py` (`lagrangian_bound`, `min_deferral`) |

The physical model (constellation, plasma-bubble field, pierce points, S4 frequency scaling, Nakagami-m × Rician fading, MCS table) is in `src/sim.py` and `src/run.py`.

## 3. Installation

Tested with Python 3.13, NumPy 2.5, SciPy 1.18, scikit-learn 1.9 and Matplotlib 3.11 on Linux.

```bash
git clone https://github.com/iitrky/ionoguard.git
cd ionoguard
python -m pip install -r requirements.txt
```

No GPU and no external data are needed: all ionospheric, orbital and channel data are generated by the simulator from fixed random seeds.

## 5. Reproducing the paper

Always set `OMP_NUM_THREADS=1`; otherwise NumPy and scikit-learn threads oversubscribe the cores when several workers run in parallel and runs become several times slower.

```bash
bash run_all.sh                  # everything, about 7-8 hours on two cores
```

The evaluation scripts skip any job whose result file already exists, so with the included `results/` they finish almost immediately and only regenerate the summaries and figures. To recompute everything from scratch, first delete `results/nights/`, `results/mu/`, `results/mu_ol/`, `results/ol/` and `results/ood/` (and `results/models_*.pkl` to retrain the models).

or step by step:

```bash
cd scripts
export OMP_NUM_THREADS=1
python train_models.py                              # only if results/models_*.pkl were deleted
python run_ext.py A & python run_ext.py B; wait     # main evaluation (jobs are claimed via lock files, resumable)
python run_ol.py A & python run_ol.py B; wait       # online risk control, single UE
python run_mu_ol.py A & python run_mu_ol.py B; wait # online risk control, multi-user
python run_sweeps.py; python run_trace.py; python timing.py; python summarize.py
python summarize_ext.py; python summarize_ol.py     # statistics -> results/*.json
python make_figures.py; python make_block_diagrams.py; python make_system_diagrams.py
python make_mu_diagram.py; python make_new_figures.py
```

Run times on one core: a single-UE test night with all ten schemes about 5 min, a multi-user night with six schemes about 13 min, a goodput bound about 12 s.

### Seeds

| Training nights (S1 / S2 / S3) | 1001–1003 / 2001–2003 / 3001–3003 |
| Calibration nights | 1011–1013 / 2011–2013 / 3011–3013 |

### Result-file format

* `results/summary.json`: per scenario and scheme, `[mean, standard deviation, 95% CI half-width]` of goodput (`gp`), BFR (`bler`), disturbed-period BFR (`dbler`), deferral, handovers, window violations, disturbed goodput, plus per-night values, the bound and the bound ratios.
* `results/stats.json`: paired Wilcoxon p-values and win counts of IONOGUARD against every scheme.
* `results/mu_summary.json`: the same for the multi-user scenario (K = 1, 2, 4), including worst-UE goodput, Jain index, per-site goodput and paired tests.
* `results/ol_summary.json`: per night, the failure rates with and without the online layer, the per-group failure rates and the Theorem 1 certificate ε′ + Bδ_h(T+1)/(γN_h).

## 7. Reliability guarantee in one paragraph

The offline calibration (Proposition 1) bounds the expected block failure rate under exchangeability. The online layer updates an offset δ_h ≥ 0 per observable epoch group from HARQ outcomes, δ_h ← max{δ_h + γ(f_t − ε′n_t)/B, 0}. Telescoping the update gives, for every night and without any distributional assumption, BFR_h ≤ ε′ + Bδ_h(T+1)/(γN_h) (Theorem 1). `summarize_ol.py` evaluates this certificate on every test night; it never exceeded 4.84% for a 5% target.

## 8. Scope and limitations

All results are obtained in simulation. The plasma-bubble model reproduces the north–south elongation, eastward drift and frequency scaling of equatorial plasma bubbles but not every feature of real events (bifurcation, westward tilts, strong-scatter saturation, phase scintillation). Satellite capacity is abstracted as K users per satellite, and only the downlink is modelled.
